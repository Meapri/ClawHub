# 고급 입력 (2단계 · 드라이버 없음)

Steam Input식 버튼 동작을 프로필마다 켠다: **길게 누르기 · 두 번 누르기 · 연사 · 토글 · 레이어 · 원형 메뉴**.
켜지 않은 프로필, 그리고 켜져 있어도 고급 동작이 없는 버튼은 지금처럼 컨트롤러 펌웨어가 처리한다 (지연·안티치트 영향 없음).

## 동작 방식

```
버튼 ──펌웨어──▶ F23 + 글자 (운반 키) ──저수준 키보드 훅(ClawApp)──▶ 판정 ──SendInput──▶ 게임
```

1. `AdvancedInput.FirmwareBindings`가 엔진이 맡는 버튼을 운반 키 `KB_F23 + KB_<글자>`로 바꿔 펌웨어에 쓴다
   (버튼마다 글자가 다르다: ↑ A, ↓ B, ← C, → D, LB E, RB F, L3 G, R3 H, A I, B J, X K, Y L, M1 M, M2 N, LT O, RT P).
2. `AdvancedInputEngine`의 `WH_KEYBOARD_LL` 훅이 **하드웨어** F23과 그 글자를 삼키고(게임에 안 보임) 작업 스레드로 넘긴다.
   우리가 낸 입력(`LLKHF_INJECTED`)은 다시 받지 않는다. 펌웨어가 글자를 F23보다 먼저 보내도 20ms 안이면 되살린다.
3. 작업 스레드(2ms 주기)가 동작을 판정하고 `SoftInput`이 스캔 코드로 키·마우스를 낸다.
4. 원형 메뉴는 `RadialMenuWindow`(포커스를 뺏지 않고 클릭이 통과하는 최상위 창)를 띄우고,
   고르기는 스틱을 XInput으로 직접 읽는다 (스틱은 펌웨어 매핑과 상관없이 늘 XInput으로 나온다).
   대각선 칸이 모두 비면 상하좌우 4칸 메뉴가 된다.

엔진은 셸이 게임 매핑을 적용할 때(`SyncControllerAsync`) 같이 켜지고, 매핑이 풀리면(허브가 앞, Game Bar 등) 멈추며
누르고 있던 키를 모두 뗀다. 앱이 꺼질 때도 뗀다.

## 판정 규칙

| 설정 | 동작 |
| --- | --- |
| 레이어 버튼 | 누르는 동안 레이어 켜짐. 다른 버튼은 "레이어 중" 키를 낸다 (그 버튼 자체는 키 없음) |
| 원형 메뉴 | 누르는 동안 메뉴, 떼면 고른 칸의 키를 한 번 |
| 토글 | 누를 때마다 "누를 때" 키를 누름/뗌 |
| 길게 · 두 번 | 길게(기본 400ms) = 그 키를 누르고 있음 · 두 번(250ms 안) = 한 번 탭 · 아니면 "누를 때" 탭 (두 번이 있으면 250ms 늦게) |
| 연사 | 누르는 동안 간격마다 탭 (빠르게 60 · 보통 100 · 느리게 200ms). 길게·두 번이 있으면 쓰지 않는다 |
| 없음 | "누를 때" 키를 누르는 동안 누름 |

## 한계 (가상 패드를 켜면 첫 번째가 풀린다)

- 엔진이 맡는 버튼은 **키보드·마우스만** 낼 수 있다. 펌웨어가 그 버튼을 키로 보내면 XInput에서 빠지기 때문.
  편집기가 게임패드 키를 막고, 카드에 경고를 띄운다.
- 소프트웨어 입력(SendInput)이라 일부 온라인 게임의 안티치트가 막거나 문제 삼을 수 있다 — 켤 때 확인을 받는다.
- 전체 화면 독점 모드 게임에서는 원형 메뉴 창이 보이지 않을 수 있다 (고르기·입력은 동작).
- 펌웨어가 F23+글자를 어떤 순서로 보내는지는 기기에서 확인해야 한다 (어느 쪽이든 처리하도록 되어 있음).

# 여러 키 차례로 누르기

여러 키를 넣은 칸은 모든 키를 동시에 누른다 (누를 때 칸은 펌웨어가). 키 선택판의 **여러 키 누르는 방식 → 차례로**를 고르면 그 칸은
차례로 나간다 — 누를 때 칸은 `MappingProfile.Sequence`, 길게·두 번·레이어 칸은 `AdvancedButton.Sequence`("long"·"double"·"layer")에 간격을 둔다
(원형 메뉴 칸은 해당 없음). 누를 때 칸을 차례로 하면 그 버튼은
엔진 버튼이 되고(`MappingProfile.Sequence` = 간격 ms, 고급 입력을 켜지 않아도 됨), 한 번 누르면 첫 키를 간격만큼 누른 채로 있다가
떼고 다음 키 … 마지막 키까지 간다 (버튼을 일찍 떼도 끝까지, 다시 누르면 처음부터). 스킬 딜레이가 긴 게임에서 동시에 누르면
첫 스킬 동작 중에 들어온 뒤 키가 씹히는데, 누르고 있으면 딜레이가 끝나는 순간 나간다.
누르고 있을 시간은 키마다 따로 (`SequenceSteps` — 딜레이가 긴 스킬만 길게), 0.1~3초, 정하지 않은 키는 기본 0.7초.
누르고 있는 동안 키보드 키는 33ms마다 눌림을 되풀이한다 (진짜 키보드처럼 — 눌림 신호로만 받는 게임이 바쁠 때 온 신호를 버려도 다음 신호로 받게).
버튼을 누르고 있는 동안의 동작(`SequenceModes`): 한 번 끝까지 · 누르는 동안 반복(떼면 그 자리에서 멈춤, LT·RT 기본) · 누르는 동안만(한 바퀴, 떼면 멈춤).
길게·두 번이 있는 버튼의 짧게 누름은 이미 뗀 뒤라 늘 한 번 끝까지.

# 스틱 → 마우스·WASD·방향키 (가상 패드 없이)

프로필 옵션 → **스틱**에서 왼쪽·오른쪽 스틱을 마우스·WASD·방향키로 바꿀 수 있다 (XInput 모드 프로필, 고급 입력을 켜지 않아도 된다).
게임이 앞에 있는 동안 `StickConverter`가 실제 패드를 4ms마다 `XInputGetState`로 읽어 `StickMapper`로 바꾼다
(마우스: 데드존 15% 뒤 제곱 곡선, 흐른 시간만큼 이동 · 키: 켜짐 50% / 꺼짐 40%). 허브가 앞이면 멈추고 누르던 키를 뗀다.
게임도 실제 스틱을 그대로 보므로 스틱을 안 쓰는 게임에 알맞다 — 게임에서 숨기려면 가상 패드를 켠다 (가상 패드가 켜져 있으면 가상 패드 쪽이 같은 변환을 하고 스틱은 0으로 낸다).

# 가상 패드 (3단계 · ViGEmBus + HidHide)

프로필 옵션 → **가상 패드**를 켜면 (드라이버가 설치돼 있어야 함), 그 프로필로 게임을 하는 동안:

```
실제 Claw 패드 ──HidHide로 게임에서 숨김(ClawHub만 봄)──▶ VirtualPad 1ms 루프 ──▶ ViGEm 가상 Xbox 360 패드 ──▶ 게임
                                       고급 입력 엔진의 게임패드 출력 ─┘   스틱 → WASD·방향키·마우스
```

- 서비스(`PadHider`)가 `HidHideCLI`로 Claw 패드(XUSB `USB\VID_0DB0&PID_1901&MI_00`, HID `IG_01`)를 숨기고
  요청한 앱(파이프에서 알아낸 실행 파일)만 볼 수 있게 등록한 뒤, `pnputil /restart-device`로 패드를 다시 시작한다
  (이미 열려 있던 게임의 XInput 핸들이 닫히고 가상 패드만 다시 찾는다).
- 앱(`VirtualPad`)은 실제 패드를 `XInputGetStateEx`로 읽어 가상 패드로 낸다. 진동은 실제 패드로 돌려준다.
  가상 패드 번호는 허브·원형 메뉴가 읽지 않는다.
- 게임이 도는 동안 유지하고, 허브가 앞에 있으면 일시정지(손 뗀 패드)만 한다 — 허브를 열 때마다 패드가 다시 연결되지 않게.
- 안전장치: 앱 연결이 모두 끊기면(크래시 포함), 서비스가 시작할 때 지난번 숨김이 남아 있으면, 서비스가 멈출 때 숨김을 푼다.
- 가상 패드에서는 고급 동작이 게임패드 버튼(M1·M2·Camera 제외 — Xbox 패드에 없음)도 낼 수 있다.

## 원형 메뉴 (SteamOS식)

- 칸 수 4·6·8·12 (8칸에서 대각선이 모두 비면 상하좌우 4칸으로 줄여 띄운다). 칸 수를 바꾸면 넣어 둔 칸은 가장 가까운 방향으로 옮긴다.
- 고르는 스틱: 자동(여는 버튼 쪽 — L3·LB·LT·방향 버튼은 왼쪽, 나머지는 오른쪽) · 왼쪽 · 오른쪽.
  고르는 스틱을 눌러 연 메뉴(L3 + 왼쪽 스틱 등)는 한 번 누르면 열린 채로 있고, 기울였다가 가운데로 놓으면 그 칸 실행,
  다시 누르면 고른 칸 실행(안 골랐으면 취소), 아무것도 안 고르고 5초면 닫힌다. 누른 채 기울였다 떼도 된다.
  고르는 동안 스틱 입력은 게임에도 그대로 간다 (가상 패드 모드가 아니면 막을 수 없다).
- 크기 작게·보통·크게, 칸 이름(비우면 키 이름), 칸이 바뀔 때 진동 틱(약하게 18ms).
- 경계에서 떨리지 않게 지금 칸에서 6°를 더 넘어야 옮긴다. 스틱을 가운데로 놓으면 고른 칸 그대로.
- 모션: 열림(살짝 커지며 칸이 시계 방향으로 펼쳐짐, ≈180ms) · 강조 칸이 가장 가까운 방향으로 돌아감 · 고른 칸이 바깥으로 5px ·
  닫힘(실행 = 반짝이며 커지며 사라짐 / 취소 = 작아지며 사라짐). 화면 전체를 어둡게 하지 않는다.
- 편집기의 "미리 보기"는 실제 메뉴를 띄워 칸을 한 바퀴 돌며 보여 준다 (키는 누르지 않는다).
