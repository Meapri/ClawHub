# AI TDP 설계

게임마다 **목표 프레임을 지키는 최소 전력**을 자동으로 찾고, NPU로 화면 상황(메뉴·컷신·로딩·전투)을 알아봐
그 상황에 맞는 목표 자체를 바꾼다. 상태: 설계 (구현 전).

## 원칙

- **AI는 "목표"를 정하고, 전력은 제어 루프가 맞춘다.** 몇 W를 줄지는 프레임 시간 피드백으로 충분하다(1~2초 주기,
  숫자 열 개 남짓). NPU는 숫자로 알 수 없는 것 — 지금 화면이 메뉴인지 전투인지 — 에만 쓴다.
- **오판해도 안전하게.** AI 판단은 전력 상한을 낮추는 쪽으로만 쓰고, 프레임이 목표 아래로 떨어지면 제어 루프가
  언제나 다시 올린다. 측정값이 끊기면 사용자가 정한 고정 모드로 돌아간다.
- **아끼는 전력 > 쓰는 전력.** 화면 분류(캡처 + 추론)가 쓰는 전력을 재서 0.3W를 넘으면 주기를 늘리거나 끈다.
- 화면은 저장하지도 내보내지도 않는다. 전부 기기 안에서 처리.

## 단계

| 단계 | 내용 | NPU |
|---|---|---|
| 1 | 목표 FPS 자동 TDP (제어 루프) + 세션 로그 | 없음 |
| 2 | 게임별 학습: 지난 세션에서 안정된 전력으로 바로 시작 | 없음 |
| 3 | 상황 인식: 저렴한 신호(입력 없음, 30fps 고정) + NPU 화면 분류 → 상황별 목표 | 사용 |
| 4 | 사용자 교정 학습: "이건 메뉴 아님" → 게임별 보정 | 사용 |

1·2단계만으로도 기능이 완결되고, 3단계는 같은 자리(목표 결정기)에 꽂는다.

## 구조

```
┌──────────── ClawApp (사용자 세션) ────────────┐        ┌──────────── ClawService (LocalSystem) ─────────────┐
│ SceneSensor (3단계)                            │  pipe  │ AutoTdpController (1초 주기)                        │
│  · 게임 창 캡처 1Hz, 224px                     │───────►│  ├ 입력: FrameMonitor(PresentMon) 프레임 시간        │
│  · NPU 이미지 분류 → SceneHint{종류, 확신도}   │        │  │       EC 패키지 전력·온도, 전원, 입력 없음 시간   │
│ 입력 없음 시간 (XInput/키보드)                 │        │  ├ TargetPolicy: 게임 설정 + SceneHint → 목표 FPS·상한│
│ UI: 빠른 설정·위젯·게임 상세                   │        │  ├ 제어: 목표 대비 프레임 시간 → PL1/PL2 한 단계      │
└────────────────────────────────────────────────┘        │  └ EcManager.SetDynamicLimits (쓰기 직렬화)          │
                                                          │ GameTdpStore: 게임별 학습값 (auto-tdp/<게임>.json)   │
                                                          └──────────────────────────────────────────────────────┘
```

- 제어 루프는 **서비스**에 둔다. PresentMon(ETW)과 EC 쓰기가 이미 서비스에 있고, 앱이 죽어도 전력 제어는 계속된다.
- 화면 캡처는 세션 0(서비스)에서 안 되므로 **앱**에서 하고, 결과(라벨과 확신도)만 서비스로 보낸다.

## 1단계: 제어 루프

### 입력 (1초마다)

| 값 | 출처 | 비고 |
|---|---|---|
| 프레임 시간 p50 / p90 (최근 3초) | `FrameMonitor` → `FrameStats` | 컨트롤러가 직접 `NotePoll()`을 불러 측정을 켜 둔다 (지금은 10초간 조회가 없으면 꺼짐) |
| 목표 FPS | 게임 설정 (`GameEntry`) 또는 FPS 제한값 | 없으면 "자동" — 아래 참고 |
| 패키지 전력, CPU/GPU 온도 | `EcManager.ReadTelemetry()` (EC 0xDD) | |
| 현재 PL1/PL2 | 컨트롤러 자신이 마지막으로 쓴 값 | |
| 전원 / 배터리 | `PowerManager` | 배터리일 때만 켜는 옵션 |

### 목표 FPS

- 사용자가 고른 값: 30 / 40 / 45 / 60 / 직접 입력.
- **자동**: FPS 제한(`IntelGraphics` 프레임 제한)이 걸려 있으면 그 값. 없으면 처음 20초간 최고 전력에서 잰 p50을
  모니터 주사율 약수(120 → 120/60/40/30)로 내림해 정한다.
- 목표보다 높게 나오는 것은 낭비로 본다 → 프레임 제한을 같이 걸 것을 권한다 (UI에서 한 번에).

### 제어 규칙

`ratio = 목표 프레임 시간 / 측정 p90 프레임 시간` (1보다 크면 여유)

| 상황 | 동작 |
|---|---|
| `ratio < 0.95` (목표 미달) | **빠르게 올림**: 부족분에 비례해 +2~+6W, 바로 적용 |
| `0.95 ≤ ratio < 1.08` | 유지 (데드밴드) |
| `ratio ≥ 1.08`이 5초 이상 | **천천히 내림**: −1W |
| 방금 내렸는데 미달 | 내리기 직전 값으로 되돌리고 그 값을 이 게임의 "바닥"으로 30초간 고정 (진동 방지) |

- **여유 조절**(설정 슬라이더 "절약 ↔ 안정"): 내리기를 멈추는 기준 `1.08`을 절약 1.03 ~ 안정 1.15로 바꾼다.
  안정 쪽은 목표보다 여유를 두고 멈춰 갑작스러운 부하에 덜 흔들린다.
- 한 번 바꾼 뒤 최소 3초는 다시 바꾸지 않는다 (PL 반영과 프레임 측정 지연).
- 범위: 8W ~ 사용자 상한(기본: 성능 모드 PL1 30W). 온도 90°C 이상이면 상한을 2W씩 낮춘다.
- 측정값이 5초 이상 없으면(일시 정지, 창 전환, PresentMon 실패) 마지막 값 유지 → 30초 지나면 사용자 고정 모드로.

### EC 쓰기 — 새 메서드가 필요한 이유

지금 `PerformanceManager.Apply`는 쓸 때마다 **PL1을 8W로 내렸다가** PL2, PL1 순서로 쓴다
([PerformanceManager.cs:39](../src/ClawCore/Ec/PerformanceManager.cs)). 몇 초마다 부르면 그때마다 순간적으로 8W가 되어 끊김이 생긴다.

`PerformanceManager.SetLimits(pl1, pl2)`를 새로 둔다:

- 바뀐 값만 쓴다. 올릴 때는 PL2 → PL1, 내릴 때는 PL1 → PL2 순서 (항상 PL1 ≤ PL2 유지, 바닥으로 내리지 않음).
- ShiftMode·Windows 전원 모드·팬은 건드리지 않는다 (AI TDP를 켤 때 한 번만 성능 모드 프리셋으로 맞춤).
- PL2 = min(PL1 + 7W, 상한 PL2). 짧은 부하(로딩, 장면 전환)는 PL2가 받아 준다.

`EcManager.SetDynamicLimits`가 `_ecLock` 안에서 이를 부르고, 저장하지 않는다(임시 값). 절전 복귀 `Reapply`는
AI TDP가 켜져 있으면 컨트롤러의 현재 값을 다시 쓴다. 게임이 끝나면 `RestoreDefault()`.

### 다른 기능과의 관계

- **Intel Endurance Gaming**: 드라이버도 전력·프레임을 바꾸므로 둘이 싸운다. AI TDP를 켜면 Endurance를 끄고
  원래 값을 기억했다가 끌 때 되돌린다.
- **게임별 성능 모드** (`ApplyTemporaryPerformance`): AI TDP가 그 게임의 성능 모드 중 하나가 된다
  (`PerformanceMode.Auto`). 수동·프리셋과 같은 자리에서 고른다.
- **MSI Center M**: 꺼져 있어야 한다 (켜져 있으면 UserScenario가 PL을 다시 써서 싸움). 켜져 있으면 AI TDP 화면에 안내.

### 세션 로그

`%ProgramData%\ClawHub\auto-tdp\logs\<게임>-<시각>.csv`: 1초마다 시각, 목표, p50, p90, PL1, PL2, 패키지 W,
배터리 W, 온도, 상황 라벨. 이걸로 효과를 잰다 (아래 "검증").

## 2단계: 게임별 학습

- 세션이 끝나면 "목표를 지킨 구간"의 PL1 분포를 저장한다: p50, p90, 목표 FPS, 전원 (`auto-tdp/<게임 id>.json`).
- 다음 실행 때 **p90 값에서 시작**한다. 지금처럼 최고 전력에서 내려오며 헤매는 몇십 초가 사라진다.
- 같은 게임이라도 목표 FPS나 전원이 바뀌면 따로 저장한다. 최근 세션일수록 가중치를 크게.

## 3단계: 상황 인식

### 상황 종류와 정책

| 상황 | 목표 | 전력 상한 | 판단 근거 |
|---|---|---|---|
| 플레이 | 사용자 목표 | 사용자 상한 | 기본값 |
| 전투·격한 장면 | 사용자 목표 | 사용자 상한, **바닥을 학습 p90으로 미리 올림** | NPU. 프레임이 떨어지기 전에 전력을 먼저 올린다 |
| 메뉴·인벤토리·지도 | 30fps | 10W | NPU |
| 컷신 | 컷신 프레임 (보통 30) | 사용자 상한 | 프레임 시간이 33.3ms에 고정 + NPU (레터박스) |
| 로딩 | 그대로 | 그대로 (옵션: 12W) | NPU. 로딩은 CPU를 많이 써서 전력을 낮추면 길어진다 — 기본은 손대지 않음 |
| 멈춤·자리 비움 | 30fps | 8W | 입력 없음 60초 + 화면 변화 거의 없음 (NPU 불필요) |

정책은 **상한과 목표만** 바꾼다. 실제 전력은 여전히 1단계 제어 루프가 프레임을 보며 정한다.

### 저렴한 신호 먼저

NPU를 깨우기 전에 이미 아는 것으로 거른다: 입력 없음 시간(앱이 이미 패드 입력을 읽음), 프레임 시간 분산과
고정값(30/60 고정 = 컷신·메뉴 후보), GPU 3D 사용률(`SystemMetrics`). 확실하면 NPU를 부르지 않는다.

### 화면 분류 (NPU)

- **캡처**: Windows.Graphics.Capture로 게임 창만, 1초에 1번. GPU에서 224×224로 줄여 받는다. HDR 게임은 SDR로 톤 매핑.
  보호된 창이나 안티치트로 캡처가 막히면 그 게임은 저렴한 신호만 쓴다.
- **모델**: MobileCLIP-S0 이미지 인코더(INT8 ONNX, 약 11M 파라미터). 미리 계산한 문장 임베딩
  ("게임 메뉴 화면", "로딩 화면", "영화 같은 컷신", "3D 게임 플레이 장면" 등 여러 표현)과의 유사도로 분류 →
  **게임마다 따로 학습하지 않아도 된다.**
- **실행**: ONNX Runtime + OpenVINO 실행기(NPU). NPU가 없거나 실패하면 CPU에서 5초에 1번.
- **흔들림 방지**: 최근 3번 중 2번 이상 같은 라벨 + 확신도 기준을 넘을 때만 상황을 바꾼다. 플레이로 돌아갈 때는 1번으로 충분
  (전력을 올리는 쪽은 빠르게).
- 결과는 `SceneHint{Kind, Confidence, At}`로 서비스에 보낸다 (새 IPC Op `SetSceneHint`).

### 4단계: 사용자 교정

빠른 설정에 지금 상황 라벨을 보여 주고 "아니에요"를 누르면 그 순간의 이미지 임베딩을 게임별로 저장한다.
다음부터 가까운 임베딩(kNN)이 있으면 그 라벨을 따른다.

## 화면

- **빠른 설정 / 위젯**: AI TDP 켜기, 목표 FPS 칩(30·40·45·60·자동), 지금 전력(W)과 상황 라벨.
- **게임 상세**: 성능 모드에 "AI TDP", 이 게임의 목표 FPS, 학습값 초기화.
- **설정**: 전력 상한, 배터리일 때만 켜기, 상황 인식 켜기(3단계), 로딩 때 전력 낮추기.

## 성능 영향

CPU·GPU·NPU가 패키지 전력(PL1)과 메모리 대역폭을 나눠 쓰므로 AI TDP 자신도 게임 몫을 조금 가져간다.

| 원인 | 예상 | 대책 |
|---|---|---|
| PresentMon (ETW) | CPU 한 코어의 1% 안팎 | FPS 표시와 같은 세션을 함께 쓴다 |
| EC 쓰기 (WMI → ACPI) | 한 번에 수 ms | 최소 3초 간격, 바뀐 값만 |
| 화면 캡처 1Hz | GPU 복사·축소 | 게임 창만, 224px. 전체 화면 최적화(독립 플립)가 풀리는지 게임별로 확인 |
| NPU 추론 1Hz | 한 번에 수 ms | 저렴한 신호로 확실하면 부르지 않음 |
| **반응 지연** (낮은 전력에서 갑자기 무거운 장면) | 1~3초 프레임 하락, 1% low 악화 | 빨리 올리고 천천히 내림, PL2 +7W 여유, 미달 시 바닥 고정, 여유 조절, 전투 감지로 미리 올림 |

감시 비용 합계는 프레임 1% 안쪽으로 예상하지만 추정이다 — 아래 부하 측정으로 확인한다.

## 검증

같은 게임, 같은 구간을 고정 모드와 AI TDP로 각각 10분씩 돌려 세션 로그를 비교한다.

**부하 측정**: 그 전에 고정 TDP와 "고정 TDP + 감시만 켬"(PresentMon·캡처·NPU 동작, 전력 조절 안 함)을 비교한다.
FPS나 1% low 차이가 1%를 넘으면 캡처 주기를 늘리거나 그 게임은 화면 분류를 끄고 저렴한 신호만 쓴다.

| 지표 | 성공 기준 (초안) |
|---|---|
| 평균 배터리 전력 | 고정 균형 모드 대비 15% 이상 감소 |
| 목표 미달 시간 (p90 기준) | 2% 이하 |
| 1% low FPS | 고정 모드 대비 10% 이내 |
| 화면 분류 자체 비용 | 데스크톱에서 켜고 끈 전력 차이 0.3W 이하 |
| 감시만 켰을 때 프레임 손실 | FPS·1% low 모두 1% 이하 |

## 정할 것

- 목표 FPS 기본값: "자동"으로 할지, 30/40 같은 고정값으로 할지.
- 전원 연결 상태에서도 켤지 (기본: 배터리일 때만).
- 로딩 화면 정책: 그대로(빠른 로딩) / 낮춤(배터리).
- PresentMon: 지금은 MSI Center M 폴더의 1.x를 쓴다. AI TDP가 이것에 기대므로 PresentMon 2.x를 ClawHub에 같이 넣을지.
